# 开发运行

## 环境

- Windows x64、PowerShell 7、Git。
- `global.json` 指定 .NET SDK 10.0.400，允许同一 10.0.4xx 功能带的更高补丁。
- 运行应用需要 SQL Server 2019 或更高版本平台数据库，兼容级别 150；运行数据库集成测试需要 SQL Server LocalDB。
- 产品 Solution 为 `DbBackupManager.slnx`。

## 构建与测试

```powershell
dotnet restore DbBackupManager.slnx
dotnet format DbBackupManager.slnx --verify-no-changes --no-restore
dotnet build DbBackupManager.slnx --configuration Release --no-restore
dotnet test DbBackupManager.slnx --configuration Release --no-build --filter 'Category!=P56TargetSqlAcceptance'
```

过滤器排除专用外部 SQL 夹具，保留 LocalDB、组件、HTTP、架构及任务语义测试。不要向默认测试会话注入真实目标配置；真实环境验收由部署者在专用目标上通过管理页面完成。

部署脚本修改的附加验证：

```powershell
pwsh -File scripts/ci/Test-DeploymentScripts.ps1 -PublishSmoke
pwsh -File scripts/ci/Check-Docs.ps1
```

事件源检查可在有相应权限的环境添加 `-EventLogSmoke`，会登记并清理唯一临时事件源。测试结果不能证明真实目标、网络和部署权限均可用。

## 配置与首次启动

Web 与 Worker 共用 Platform DB 和业务凭据 Key Ring；Cookie Key Ring 只属于 Web。配置示例见[部署与运维](部署与运维.md)，所有路径须为独立受保护目录，真实值放在 User Secrets、环境变量或发布目录外配置文件中。

开发时两个项目共享 UserSecretsId，可以从 Web 项目写入：

```powershell
dotnet user-secrets set 'ConnectionStrings:PlatformDatabase' '[REDACTED_SECRET]' --project src/DbBackupManager.Web
dotnet user-secrets set 'DataProtection:CookieKeyRingPath' '[ABSOLUTE_PROTECTED_COOKIE_KEY_DIRECTORY]' --project src/DbBackupManager.Web
dotnet user-secrets set 'DataProtection:BusinessCredentialKeyRingPath' '[ABSOLUTE_PROTECTED_BUSINESS_KEY_DIRECTORY]' --project src/DbBackupManager.Web
```

上述占位符不是可运行值。先创建专用目录、配置最小权限，再填入自己的连接和路径。不要复用生产平台库进行开发测试。

应用不会自动迁移数据库。核对目标后手动执行：

```powershell
dotnet tool restore
dotnet ef database update --project src/DbBackupManager.Infrastructure --startup-project src/DbBackupManager.Web --context PlatformDbContext -- --environment Development
dotnet run --project src/DbBackupManager.Web --configuration Release --launch-profile http
```

浏览器打开 `http://localhost:5080`，完成首次管理员设置与登录。先保存业务凭据生成有效业务 Key Ring，再启动 Worker：

```powershell
dotnet run --project src/DbBackupManager.Worker --configuration Release --launch-profile Development
```

需要 HTTPS 调试时为 Web 选择 `https` profile，地址为 `https://localhost:7080`。生产 Windows Service 不使用 launchSettings 或 Development，遵循[部署与运维](部署与运维.md)。

`/health/live` 表示 Web 进程可响应；`/health/ready` 只检查平台数据库连接就绪，不证明 Migration、业务权限、Worker 或目标存储健康。管理页面显示 Worker 心跳；心跳在线也不等于备份执行成功。

## API 开发

业务接口从 `/api/v1` 开始，契约见 [OpenApi/v1.json](../src/DbBackupManager.Web/OpenApi/v1.json)。使用同源管理员 Cookie；非安全方法必须携带 `X-CSRF-TOKEN` 和 `GET /api/v1/auth/csrf` 设置的防伪 Cookie。身份变化后重新获取 Token。API 不提供 Bearer Token 或 API Key。

Development 暴露 `/openapi/v1.json`。修改 API 后先构建、审查生成差异，再同步契约并运行 Web 测试：

```powershell
dotnet build src/DbBackupManager.Web --configuration Release
Copy-Item src/DbBackupManager.Web/obj/openapi/v1.json src/DbBackupManager.Web/OpenApi/v1.json
dotnet test tests/DbBackupManager.Web.Tests --configuration Release
```

不得手工改契约掩盖漂移。错误响应为稳定 Problem Details 与错误码，不返回原始异常；读取所得 `Version` 用于并发检查，不自行构造。

## 工程与 CI

中央依赖版本在 `Directory.Packages.props`，工程约束在 `Directory.Build.props`；更改项目引用或依赖后先重新 restore，再运行架构测试。OpenAPI 与行为保持一致。

GitHub Actions 对主干和 PR 运行分层构建/测试及文档检查；初始提交会运行完整 CI。UI 预览可用 [UiPreview](../tests/DbBackupManager.UiPreview/README.md)，它使用随机 LocalDB 和演示数据，不访问真实 SQL 或文件存储。
