# 使用指南

## 首次配置顺序

1. 按[开发运行](开发运行.md)或[部署与运维](部署与运维.md)启动 Web，完成首次管理员设置。
2. 在 SQL 凭据页面保存目标 SQL 登录；在暂存访问凭据页面保存 SMB 或 SFTP 凭据。密码、私钥及口令保存后不回显，轮换凭据应使用对应修改操作。
3. 添加服务器，配置 SQL 本地备份根和 Worker 暂存访问映射。二者必须指向同一物理目录：SQL Server 在前者生成备份，Worker 从后者读取文件。
4. 添加 SQL 实例并选择凭据，先测试连接，再发现并纳管数据库。发现操作只读取目标信息，不执行备份。
5. 需要远程副本时添加存储目标，选择 SMB 或 SFTP 协议及匹配凭据。SFTP 必须填写已经独立核对的主机密钥指纹，不自动信任未知主机。
6. 保存业务凭据后启动独立 Worker，核对心跳与服务状态，再配置备份计划。

连接测试只检查既定对象，不证明写入、目录创建、删除或备份权限全部具备。目标连接异常时先看中文错误分类；密钥缺失或密码解密失败不能靠改变账号前缀解决。

## 备份计划

每个已纳管的非系统数据库只有一个当前备份计划，暂停后仍占用该位置。在“备份计划”页面查看、创建和编辑模式、时间、时区、存储位置、恢复窗口和超时。本阶段只保存完整备份，或完整备份加差异备份；页面不提供日志备份，保存时也不会提示开启日志备份。CHECKSUM 默认勾选，压缩由管理员选择。

保存计划只写入配置。自动调度、计划执行循环和定时删除当前没有启用。Worker 仍只自动领取既有策略任务，保存差异计划不会因此开始自动执行。计划任务运行时出现的明确失败、结果未知和远端暂时无法恢复，会按下文通知入队；页面没有立即执行入口，该运行由内部计划任务入口触发。并发保存时，若计划已被其他人修改，或该库已经有当前计划（含已暂停），页面会提示刷新或改用现有计划。

| 存储模式 | 行为 |
|---|---|
| 仅本地 | 只记录本地恢复窗口；当前执行仍是既有完整备份并校验本地副本 |
| 本地加远程 | 本地与远端分别记录恢复窗口。当前执行仍先校验本地副本，再传输到远端 |
| 仅远程 | 只记录远端恢复窗口。计划任务仍先在 SQL 端生成并校验暂存；只在当前文件及其远端恢复依赖都确认后才清理暂存。远端尚无基准完整备份时，该位置暂时无法恢复，必要暂存继续保留 |

可恢复摘要按存储位置显示。没有当前计划时不合成恢复窗口。位置事实未知时显示为不健康，不会显示为可恢复。远端暂时无法恢复时单独标明，它可以和未知同时出现。

任务列表显示实际备份类型、计划版本，以及 SQL 执行、文件校验、传输和恢复依赖。未知不会当成成功。旧策略产生的任务没有计划版本。文件列表关联逻辑备份集，显示差异基线和保留原因；本页证明不了的依赖继续显示为未知并受保护。

目录按服务器、实例、数据库和类型分层，Worker 仅在已配置根内准备缺失层级。配置保存后不等于已备份。旧的手动配置和计划备份页面仍可打开，但不再是产品入口，也不会再承接新功能。暂停计划不能代替取消已创建任务，也不能用于整体关闭后台访问。

## 任务状态与人工处置

- `Pending` 为等待执行，`Running` 为正在执行，`Succeeded` 表示该任务既定阶段完成。
- `Failed` 为明确失败，可按界面发起独立重试；重试使用新 Attempt 和新文件名。
- `NeedsAttention` 表示外部执行结果尚无法确认。系统会尝试只读核对，不自动再次 BACKUP。
- 取消是请求；外部调用已发生且结果不明时可能仍需核对，不能把关闭页面或连接中断视为安全取消。

处理待核对任务时，先检查目标 SQL 活动请求、本次 Attempt 对应文件及完成备份记录。可在详情页请求重新核对；证据确实表明失败时，由管理员明确确认失败后再决定是否重试。确认失败不自动备份、不移动或删除文件。不要直接改状态表。

`RESTORE VERIFYONLY` 不等于完整还原演练；实际恢复流程及业务一致性须在隔离库验证。

## 文件和保留清理

任务详情与备份文件页展示平台登记的副本和校验事实；不会把任意目录文件自动纳入管理。远程传输使用 `.part`、长度检查和同目录不覆盖重命名，冲突或不确定结果保留待核对状态。

Retention 只处理系统登记且满足到期条件的文件，并保留每组至少最新一份；不扫描任意文件进行删除。页面显示历史校验状态，文件缺失、权限或删除失败需要按错误分类处置。

## 通知、工作台与权限

在通知设置中配置 SMTP、收件人及启用状态。测试通知先进入 Outbox，由 Worker 投递；Web 页面提交成功不代表邮件已送达。传输保护默认启用，明文 SMTP 仅允许显式登记的受控例外。

明确失败和结果未知在提交运行事实的同一短事务里登记邮件。远端暂时无法恢复在该事实提交之后单独投影入队；需要投影时，待补发标记与事实写在同一事务。投影成功后清除标记。投影失败或未能取得保留锁时标记留下，后续计划阶段提交、清理、计划保留删除或读取恢复摘要碰到该库时再补做，不因此打开后台循环，也不撤回已经提交的运行事实。正文只有任务短标识、阶段、UTC 时间和稳定错误码，不含路径、账号、主机或连接信息。日志同样不含这些内容，也不写异常详情。

| 情况 | 邮件主题 | 含义 |
|---|---|---|
| 明确失败 | 备份失败通知 | 调用前拒绝或 SQL 明确失败。系统不自动重发 BACKUP |
| 结果未知 | 备份结果未知 | 外部结果还不能确认。只做只读核对，未知保持待核对。核对后来确认成功时不补发邮件 |
| 远端暂时无法恢复 | 远端暂时无法恢复 | 仅远端位置。已有恢复缺口，或该位置已确定不可恢复且该结论不是未知。未解析的活动基线只属于未知。同一数据库、同一远端目标和同一缺口在恢复前只发一次。位置未知，或这次没有投影到该目标时，不新开也不关闭已有缺口。只有位置已不是未知、不是远端暂时无法恢复、且结论可恢复时才算恢复；恢复后再次出现可以再发一封 |

数据库处于完整恢复模式、计划只做完整备份或完整加差异时，保存、工作台和邮件都不产生开启日志备份的建议。计划副本在显式删除中确认失败或发现缺失时，沿用副本删除失败和副本缺失通知。定时删除保持关闭，这些通知不打开删除循环。

工作台汇总任务、失败、副本和 Worker 心跳；任务/文件列表支持筛选和分页。实时通知触发重新查询，重连后以数据库快照为准。Worker 在线仅说明近期心跳，不代表外部依赖和整个任务循环都健康。

管理操作要求管理员身份，并检查并发版本。出现并发冲突先刷新，出现身份失效重新登录。不要在截图或问题报告中包含真实端点、账号、路径、密钥或业务数据。
