# 架构说明

## 进程与分层

项目采用 .NET 10：Blazor Interactive Server、API 与认证位于同一个 Web 进程，独立 Worker 从 Platform DB 领取和执行后台任务。Web 离线不会阻止 Worker 工作，浏览器连接不是执行任务的前提。

| 项目 | 职责 |
|---|---|
| Domain | 业务模型、状态机与不变量，不依赖其他项目 |
| Application | 用例和端口，不依赖 ASP.NET Core、MudBlazor 或 EF Entity |
| Infrastructure | EF 持久化、SQL、文件存储、邮件与凭据保护 |
| Contracts | 公开 API 请求和响应类型 |
| Web | 页面、Controller、Cookie/CSRF、输入输出映射与事件 Relay |
| Worker | 心跳、定时 Retention、通知循环，以及计划调度与执行循环。不注册恢复循环 |

Blazor 直接调用 Application，不通过 HTTP 回调自身 API。Web 与 Worker 共用 Platform DB，但备份目标使用独立连接和适配器。部署为单 Web、单活动 Worker；多节点不在当前范围。

## 数据与凭据

Platform DB 最低 SQL Server 2019、兼容级别 150。只通过非池化 `IDbContextFactory` 创建短生命周期 Context；SQL Backup、SMB/SFTP 和 SMTP 等外部 I/O 期间不持有 Context 或数据库事务。

管理员、凭据、源服务器/实例/数据库、备份计划、任务/Attempt、文件副本、状态历史、审计、通知 Outbox、TaskEvent 和 Worker 心跳分别持久化。旧备份策略模型已经从产品和当前模型移除。迁移 `20261013120016_RemoveBackupPolicies` 遇到仍有旧策略、策略任务或缺少计划身份的任务时抛出 `51008` 并拒绝升级；不转换、不归档。应对方式是新建空的平台库后再升级。模型与 Migration 位于 Infrastructure；进程启动不会自动迁移。

Cookie 与业务凭据使用分开的 Data Protection Key Ring。业务密钥由 Web/Worker 共享，Cookie 密钥仅授予 Web；密文和密钥应随平台数据库按一致时间点保护与恢复，不能只备份数据库。

## 执行安全

任务保存不可变执行快照，Attempt 使用独立文件名与阶段事实。执行和核对通过租约、心跳与并发版本争用，失去提交资格的进程不能回写成功结果。

计划任务创建由 Application 区分管理员手动请求与内部时隙请求；只接受普通 FULL、DIFF 和手动 COPY_ONLY FULL，LOG 返回阶段未开放。手动请求必须指定当前计划版本，自动请求必须属于指定版本的有效 UTC 时隙；暂停计划阻止新的自动请求，管理员仍可手动创建。执行快照从平台配置及不可变计划版本组装，固定用途对应的类型、COPY_ONLY 和 v3 路径规则。

创建任务、快照、状态历史、审计及 TaskEvent 在同一短事务中提交。MutationId 绑定完整请求身份，重放不重建快照或追加记录；同槽竞争只保留一份任务，返回已有任务的请求也记录自己的幂等关联。后续配置修改不改变快照。创建成功仅表示 Pending 已入库。DIFF 只有已核对的受管普通 FULL 才能执行。Worker 以可配置间隔串行领取至多一个计划任务；结果未知只核对，不重发 BACKUP。计划创建和补基线不调用目标 SQL 或文件端口。

计划组合调度由 Worker 后台循环调用 `BackupPlanScheduler.RunOnceAsync`。单个计划的调度异常留在该计划，不中断循环；取消和平台库故障仍向上传递。每种类型只选择最近的到期时隙，按不可变版本的生效和结束边界计算；同刻或更晚的 FULL 取代旧 DIFF，明确失败的 FULL 才允许重新判断 DIFF。手动任务不作为定时时隙事实，已有任务不会自动重建或重试。没有已核对基线的定时 DIFF 在选择任务时以 `baseline_required` 收口为终态，不改成 FULL，也不记成该时隙未调用。选择时完整备份优先，不可执行的任务在 SQL 中排除，避免一批差异备份挡住后面的完整备份。

FULL 时隙成功须由同一 Attempt 的 SQL 成功、备份头与历史核对通过、本地校验成功共同证明，远端失败或远端阶段待核对不抹掉这三个事实；备份、本地校验待核对及缺失或冲突的事实保守视为不确定。当前 Attempt 尚不能证明成功时，只有全部 Attempt 均明确失败且无矛盾、核对通过或本地校验证据，才把 FULL 时隙判为失败；后续失败不能覆盖历史证据，Prepared 不作为明确失败依据。没有 Attempt 时也不能仅凭 Failed 放行 DIFF，只有明确的认领前准备失败历史才证明未执行。所有历史 FULL 处置均参与取代判断。每个计划在独立的短事务内锁定计划并串行化读取版本、暂停状态及任务事实，共用创建流程，整份决定原子提交；提交重放重新读取事实，不追加空转记录。配置无效只影响该计划，取消及平台库故障向上传递。该入口不读取活动基线、不连接目标 SQL、不访问文件。旧的领取入口已删除。当前 Worker 的计划循环一轮至多执行一个任务。执行认领在事务内先取得全局 `plan-execution` 应用锁，再确认没有租约未过期的 Running 任务，因此两个库不能同时被认领。未终止授权仍在授权阶段按数据库拒绝，并把该任务记成 `sql.database_blocked`。Worker 选择时若还有未终止授权或 Running、Indeterminate 的 Attempt，本轮等待，不开始新的 BACKUP。租约到期只进入只读核对，不表示 SQL 已停止。结果未知的下次核对时间会持久化，从 15 秒指数增加到最多 30 分钟；未到时间的任务不占用本轮。单个计划的调度、执行或核对异常记为警告并隔离，取消仍向上传递。

执行阶段为 Backup、VerifyLocal、Transfer、ValidateCopy、Cleanup，按存储模式选择需要的阶段。调用 BACKUP 前准备目录并检查任务专属文件不存在；远程输出先写 `.part`，确认后在同目录重命名，拒绝覆盖。

SQL 调用后取消、失联或进程中断可能使结果不确定；此时保留 `NeedsAttention`，不能自动重发 BACKUP。页面和 API 不再提供重试、重新核对或确认失败。结果未知时保留记录。Retention 只删除已登记到期文件，并维持至少一份保护底线。定时删除保持关闭。

计划执行的调用授权使用平台数据库协调对象：短事务对快照 DatabaseId 对应的 ManagedDatabases 行加锁，检查持久授权与遗留未终止调用，再原子保存授权及 Attempt Running。每个数据库最多一个未终止授权，每个 TaskId/AttemptId 只授予一次；重放不返回新的调用能力。租约过期、任务终结或进程重启不能解除阻塞。明确成功和明确失败响应在同一事务冻结事实、保存阶段结果并终止授权；结果不确定保持阻塞。恢复或人工确认改写遗留 Attempt 状态前，在相同协调锁事务内为无授权的 Running/Indeterminate 调用保存 Unknown 授权；它只保留阻塞，不补造会话身份或授予调用权。恢复解除必须同时证明原调用结束、旧调用者不可再次调用、原身份一致及备份头/msdb 对应成功，未知会话不能据恢复结果解除。

执行操作保存 Reserved/Frozen/Applied/Abandoned 回执及只追加的来源观察，MutationId、任务/Attempt、类型、序号和预定备份集标识固定；冻结后的载荷及观察不能改写。续租在任务行锁短事务中提交；续租改变 RowVersion 时，仅在原租约、Attempt、用途和阶段仍相同且未过期的前提下，最多重放两次同一持久化命令，不重放 SQL 或文件 I/O，真实失租立即拒绝。计划执行心跳每 20 秒将租约续至 2 分钟：单次失败或瞬时异常只重试，不取消正在进行的 BACKUP；只有确认失租，或临近到期仍未续上，才取消外部 I/O。续租异常不覆盖已经返回的执行结果。阶段提交后若不再持有原租约，且该阶段不是当前存储模式的最后阶段，执行入口返回失租。执行过程中的意外异常会尽量以 `plan.unexpected_error` 暂停并写入审计，然后继续抛出原异常。持久化命令已经执行但响应没有交回调用方时，不再追加第二次暂停，以免覆盖可能已经提交的租约和事实。Admission 的 SQL GUID 身份绑定与冻结原子保存，SQL 已开始后不能反填。元数据继续使用 BackupLsn 与 numeric(25,0)，SQL 本地时间保持原值；内容证据保存 SHA256 算法、完整 binary(32) 摘要、长度、可空对象标识及保护能力。未知内容整组为空，句柄不持久化；远端仅有长度或历史回执不能成为计划副本 Available 的依据。

计划专用 Application 入口执行指定 TaskId，开放普通 FULL、DIFF 和临时 COPY_ONLY FULL 的 LocalOnly、LocalAndRemote 和 RemoteOnly。LOG 在领取前返回阶段未开放，不创建 Attempt。临时 COPY_ONLY FULL 可以执行，但不作为受管基线。DIFF 在没有已核对受管普通 FULL 时不领取。领取、原 Attempt 路径及 SQL 操作预约原子保存；调用前绑定一次 SQL 会话与数据库 GUID，只有共享授权的首次明确成功响应允许消费一次调用权。DIFF 在授权前两次读取活动基线并核对受管普通 FULL 及其本地事实，调用后仍按实际头/msdb 解析历史依赖。调度成功不授予执行资格，外部 FULL 不创建受管备份集。

SQL 成功、元数据、本地校验与远端确认分别冻结并提交；冻结载荷与阶段、备份集、副本、附属记录及 Applied 回执在同一短事务交接。新的文件均关联原 BackupSet。首次传输和重命名预约与取消在同一任务行锁事务内协调；取消先提交时不预约远端写入，保留 SQL、元数据、本地副本及已存在的 .part。元数据读取、VERIFYONLY、SHA-256、传输与重命名期间没有平台 Context 或事务。SMB 源、目标及路径祖先以真实句柄保护，元数据与源摘要一起冻结，源保护跨越元数据读取、本地验证及登记；DIFF 提交同时校验实际 FULL 的保护句柄。传输比较源、实际发送和全量回读摘要，重命名不覆盖；最终对象保护保持到登记提交结束。只有长度、失效保护或冲突对象不足以登记 Available，SFTP 暂不提供计划执行所需能力。

`ReconcilePlanTaskOnceAsync` 只读原 Attempt、原文件和持久回执，不创建 Attempt，不 BACKUP、复制、重命名或删除；新合法租约只能应用原冻结事实或追加新的只读观察。原会话仍活动或终止可见性不足时，保存 SQL 成功但保持 NeedsAttention/Backup；冻结回执原样重放，后续显式核对另追加终止观察，正向确认终止才解除授权并推进，已确认完成时间不重写。未预约写入的阶段可以恢复为原阶段 Pending，已有预约但对象不足以证明完成时保持 NeedsAttention；后续写入须再次显式执行。Worker 对 NeedsAttention 或已到期仍为 Running 的计划任务调用 `ReconcilePlanTaskOnceAsync`，不因此重发 BACKUP。页面和 API 不提供重试、重新核对或确认失败。空转的旧执行 Worker 和恢复 Worker 已经删除。计划首次启用差异、版本改为含差异，或从暂停恢复且当前版本含差异、又没有已核对的受管普通 FULL 时，保存计划会在同一事务排队一份计划内普通 FULL。启用事件的 MutationId 来自保存请求，并按计划内递增序号唯一；同一版本可以因再次恢复再记一次，同一次保存重放不重复补。补出的任务使用 BaselineSupplement 触发类型，不占用手动执行。未知、未受管、不一致的活动基线，以及尚未结束的普通 FULL，都不自动再补。三个读取入口仍只读。

定时 Retention 不领取计划副本，定时删除保持关闭。计划正式副本的删除只走显式的按位置恢复评估：每个位置用当前计划版本的恢复窗口调用既有保留规则，未知依赖、未证明的归属、活动任务和活动基线未能解析都保持受保护。RemoteOnly 本地暂存不进入该位置的恢复链，也不能因恢复窗口被这条入口删除。只有当前文件及其远端恢复依赖都已在同一远端目标确认为唯一已证明的 Available 副本后，才由该任务的 Cleanup 阶段或显式暂存清理入口删除；远端只有 DIFF、基准 FULL 尚未到达时，该位置结论为不可恢复，必要暂存继续保留；保留成功时的状态变更和审计使用具体原因，例如 `remote_base_unconfirmed`，不把位置说成已经可恢复。显式暂存入口不领取所属任务仍为 Running 的副本。文件在解开前已经缺失时不写成已清理，任务以 `remote.staging_missing` 待核对。仍被后续 DIFF 使用的 FULL 暂存，以及依赖它的 DIFF 尚未在远端确认时，即使这份 FULL 自己已经到达远端也不删除，以便 DIFF 继续核对本地 FULL。LOG 暂存不释放。只有计划任务、v3 命名规则且已关联备份集的副本进入这些路径。删除领取与备份集/副本登记共用数据库协调锁，等待盖过 60 秒物理删除；刷新先取协调锁再锁副本行。物理删除期间另用会话锁挡住新的依赖登记，平台 Context 不跨越文件 I/O。文件已经确认解开后，即使租约刚刚到期也记为已删除，不能改回可用。尚未解开、且已经到期又不再可删的租约，先在事务外探测文件，仍在则回到可用，已经不在则记为缺失。基线副本处于待删除时，已验证的依赖登记直接拒绝。未到期且不再可删的计划租约会取消，持久化因此允许从待删除回到可用。按位置保留和暂存清理都没有接入 Worker 定时循环。计划调度与执行由单独的 Worker 循环串行处理；定时删除和依赖删除定时器仍关闭。计划 `.part` 重传删除同样拒绝。按 Attempt 清理路径也检查已登记引用，不能绕过关联备份集或矛盾归属保护。归属不明的副本继续拒绝删除。LocalDB 与本机回环 SMB 实证不替代实际目标版本、网络故障及隔离还原验收。

## 状态与通知

状态、历史、审计和事件以短事务原子保存。TaskEvent 只携带失效提示，中央 Relay 发布后逐条确认；允许重复投递，页面重新查询当前事实。首次进入、重连和定期校准也会查询，不能依赖一条实时消息作为唯一状态来源。

Outbox 邮件采用至少一次投递。计划任务的明确失败写入「备份失败通知」，结果未知写入「备份结果未知」，二者与状态、历史、审计在同一短事务提交。未知保持待核对，不改记为失败，也不因此重发 BACKUP；只读核对后来确认成功时不补发邮件。远端暂时无法恢复在该事实提交之后单独投影：只在远端位置、且投影为恢复缺口或已确定的不可恢复时入队，未解析基线只算未知。投影读取整库恢复面，不放进登记事实的事务。需要投影时，待补发标记与事实写在同一事务；投影成功后，在投影事务里只清除这次已经投影的目标；尚未投影的目标留下。失败或未能取得保留锁时标记留下，之后由阶段提交、清理、远端副本删除、计划保留删除，以及计划执行这条写路径碰到该库时补做。不另做启动补做。读取恢复摘要保持只读，不写库、不拿锁、不入队，也不回滚已经提交的事实。同一数据库、同一远端目标和同一缺口在恢复前只保留一封，并发插入由未恢复行的唯一索引挡住。位置未知或这次没有该目标的投影时，不新开也不关闭已有缺口；只有位置已不是未知、不是远端暂时无法恢复、且结论可恢复时才关闭。关闭后再次出现可以再发。投影失败或未能取得保留锁时只记警告，日志不含路径、账号、主机、连接或异常详情。任务已经结束、当前阶段为空时，这封通知记在 Cleanup。完整恢复模式配合不含日志的计划不产生日志备份建议。计划副本的显式删除失败和缺失沿用原 Retention 通知。通知投递仍由既有通知 Worker 循环完成。计划调度和执行由单独的计划循环处理；定时删除和依赖删除定时器仍关闭。TaskEvent 默认保留已发布事件 30 天、最多 200,000 条；未发布事件受保护，状态历史独立保留。

## 安全边界

- 同源管理员 Cookie、CSRF、限流、安全戳复核与并发控制；API 使用稳定 Problem Details，不回显原始异常或秘密。
- SQL、SMB、SFTP 凭据加密保存；SFTP 必须核对 Host Key，路径访问限制在配置根内，拒绝路径越界及重解析跳转。
- Production HTTP、旧 SQL/TLS 与明文 SMTP 只在受控环境显式启用；已验证边界见[兼容与已知限制](../README.md#兼容与已知限制)。
- 认证、任意删除、结果不确定时重试和兼容范围的变化属于需要维护者审查的架构决策。

API 的完整字段及错误码以[OpenAPI](../src/DbBackupManager.Web/OpenApi/v1.json)为准，生成与验证方式见[开发运行](开发运行.md)。
